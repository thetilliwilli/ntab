# CLAUDE.md

Notes for Claude Code sessions on this repo. Read README.md for features and the file map, PUBLISHING.md for
store releases, the header of `shared/db.js` for the data model, the header of `apps/notes/notes.js` for the
save/session model, and `shell/apps.js` for the app contract.

## The user

- Speaks Russian: answer in Russian. Code, comments, UI text, commit messages and docs stay in English.
- Priorities: the user's own productivity and speed come first; strict, square, minimal design.

## Working rules

- CLAUDE.md holds only lasting rules and decisions. Plans, ideas and temporary notes go to BACKLOG.md.
- Commit to `master` after each finished change (no need to ask). Push to `origin`
  (https://github.com/thetilliwilli/ntab, public) only when asked.
- Verify changes in the headless test harness (see Testing) before committing; check screenshots for visual work.
- No npm dependencies, no build step, no frameworks. `package.json` exists only for `npm run release`.
- Before publishing anything outward (store, GitHub settings, …) confirm with the user.

## Product decisions (don't undo without asking)

- Chrome Web Store: the live version, its permissions and commit are in `store/published.json` (the user runs
  `npm run release:done` after publishing). Releases: `npm run release` (see PUBLISHING.md); the user uploads by hand.
- When a user-visible feature changes, update `store/description.txt` (feature list and WHAT'S NEW) in the
  same commit, and `store/demo.mjs` / the scenes in `scripts/release.mjs` if the screenshots would be wrong.
- Store screenshots and promo tiles share one style: light theme only. Screenshot 1 (the title one, also on the
  marquee tile) is always the home screen with its tiles; the apps come after it.
- Extension name: "NTab: Notepad New Tab" (`short_name` "NTab"; was "Custom New Tab" in v1). "New tab" and
  "notepad" are in the name for store search; no keyword stuffing. Page title: "new" on the home
  screen, the app's name in an app (`shell/main.js`).
- Favicon and extension icon: blue "N" in a square frame, `icons/icon.svg` (source) → `icon-16/32/48/128.png` (rendered with
  `magick -background none -density 1152 icons/icon.svg -resize NxN PNG32:icons/icon-N.png`).
- Storage (2.2.0, the user's choice): everything in IndexedDB (`shared/db.js`), works the same in the extension
  and the PWA. No File System Access API, no OPFS, no files, no `localStorage`/`chrome.storage` for data
  (only the theme is cached in `localStorage` for the first paint). One strict model for all entities, in every
  store, the local ones too (the user's wish): uuid `id`, `updatedAt` (set by `db.js` on every write), `name`, `…At`
  times in ms, numeric fractional `rank` (a move changes one record: `rerank` in `shared/model.js`), `kind` for the
  sort of a record; keep it consistent when adding fields. Data model 2 (database `ntab2`): no `meta` key-value store;
  `settings` is one record per setting, `device` holds this browser's records (session, backup, sync), fixed ids in
  `shared/model.js` (the default actions too, `updatedAt: 0` until changed: they give way to a server's or a backup's
  actions).
- Backups: one JSON file (`shell/data.js`). Import only adds records whose id isn't here yet (no confirm needed); a
  record that exists here stays as it is, even if the backup's differs (the user's choice: "the current one always");
  added ranked records go after the existing ones. Nothing is ever lost by an import. Only backup format 2 is read. "Import text files" adds
  notes; a note downloads as a file named exactly like the note (never append `.txt`). Backup reminder on home
  every 7 days, "Later" = 3 days. Per-entity exports other than a single note were declined for now. "Delete all data…" in Data deletes
  the database and `localStorage` after a confirm (fresh start with the default actions); the sync server keeps its data.
- No migrations: 2.2.0 started over (the 2.1 folder and `chrome.storage.sync` actions are not read; old notes come
  back through "Import text files"). The v1 shortcuts migration was removed on purpose too. Existing lists don't get
  new actions automatically (the editor has "+ <app>" buttons, "add it back" for the notepad and warns when saving
  without it). The user explicitly declined these migrations. Data model 2 started over again: 2.2's database `ntab` is
  not read (left untouched); its data comes over through format 1 backups and `scripts/migrate-backup.mjs`, which joins
  the backups of several devices into one format 2 file (the user's choice, instead of conversion code in the app).
- Sync server (`server/ntab-server.mjs`, the user's own, one person): offline first, a client works without one and
  sends everything when it connects. Node with no dependencies (`node:sqlite`), HTTPS only with a self-signed
  certificate the user makes with one `openssl` command and trusts on each device (never generated by the server,
  never in the repo); flags `--token` (basic auth, token as user or password, checked on every request but a CORS
  preflight; a flag, not an environment variable), `--listen ip:port`, `--origin` (list or `*`), `--cert`, `--key`,
  `--data`. No ban for wrong tokens, no encryption of the data itself (HTTPS is the protection). The newer
  `updatedAt` always wins, notes too (no conflict copies, no merging of text). First connect with data on both sides:
  Merge / Replace this device. Disconnect pauses (the outbox keeps collecting). Sync runs only while a page is open.
  Not in the extension zip or the PWA files.
- Web version (PWA) on GitHub Pages, served from `master` root (`.nojekyll`): https://thetilliwilli.github.io/ntab/.
  `platform/web.js` (no favicons, no site access: request "Allow access" is hidden). `sw.js`: cache-first, the whole
  file set per `VERSION`, `skipWaiting` (the next load gets the new set, never a mix); the page calls `reg.update()` when it becomes visible and
  `shell/update.js` reloads into a new version on home with no dialog open or when hidden, else shows a Reload bar; run `node scripts/sw.mjs`
  before every commit that changes app files. Web-only files stay out of the extension zip (`release.mjs`). Target:
  desktop first; mobile layout is later (Android only, iOS is not supported).
- Apps: notes, tracker, board (`apps/<id>/`, registered in `shell/apps.js`). The extension name stays
  "NTab: Notepad New Tab".
- Tracker decisions: an entry is one record `{id, typeId, at, endAt?, updatedAt}` (event: no `endAt`; activity: `endAt` null
  while running); types `{kind: "event" | "activity"}` with an emoji icon; types are archived (`archivedAt`),
  never deleted; undo toast, day log with start and finish time edit. "Delete all log entries…" (edit types
  dialog, confirm + undo) empties the log, types stay.
- Board: fixed columns new / planned / work / hold / done; drag on pointer events (works with touch), status also in the
  task dialog.
- No keyboard shortcuts (hotkeys) for now.
- No warning for large files.
- Theme colors stay our own tokens: Chrome has no API to read its theme colors (only light/dark is known);
  matching the default Chrome palette was offered and declined.
- Home screen: every page load (new tab, reload, restart) starts at home, so notes never show by themselves
  (screen sharing). Screens are hash routes (`#/notes`), replaced, never added to history; a route in the address
  on load is dropped. An app loads its data when first opened on the page.
- Home screen corner: a GitHub corner (octocat triangle, top right, new tab) to the repository and the version beside it,
  both `position: fixed` out of the layout (they never change sizes or add scroll; only the triangle takes clicks)
  (`manifest.json` version; the web version adds "build <sw VERSION>").
- Actions (the user's concept): every tile is a button = `kind` + `options`; no link/app split. Kinds: `open`
  `{url, newTab}` (`#/<app id>` opens an app, anything else is a web address) and `request`
  `{url, method, headers, body, render}` (shows the response as text, JSON pretty-printed; no images or other binary
  rendering, the user wants text answers). `render` is a JS function the user types, `w => …` with
  `w.document` (the response parsed by DOMParser), `w.text`, `w.json`, `w.url`; default `w => w.text`; its result
  (HTML or text) is on the default "render" tab, the response itself on "raw". It runs only in the sandboxed frame
  `shell/render.html` (MV3 forbids eval elsewhere); its messages are data, never trusted. Future features are new kinds. One list in `rank` order drives home
  and the sidebar, no groups. The "+ Add" tile (last) opens the action form (`#add`) for any kind, not the full
  editor (✎); the editor's ⚙ opens the same form for a row. Right-click a tile or sidebar icon: Edit (the form),
  Delete (no confirmation, like notes).
- Privacy of tiles: a site opened from a tile gets no opener and no referrer (`<meta name="referrer" content="no-referrer">`
  in newtab.html, index.html and render.html, `rel="noopener noreferrer"` on links); `test/extension.mjs` and
  `test/web.mjs` check it.
- Requests and CORS: `optional_host_permissions` for all sites, granted one site at a time from the result window
  ("Allow access to <site>") after a failed request; never `host_permissions` (install warning, review). Unknown kinds or
  apps are hidden and kept. Uploaded icons are 128×128 PNG data URLs in the action's `icon`; the editor's "Embed icons" stores the cached
  favicons the same way (so a backup carries them to the web version), "Reset icons" drops all, ↺ on a row drops one; all in the draft (Save).
- Sidebar: always narrow (60px), icons 32px, hover flyout with name + URL, arrows above and below the
  icons when they don't fit: in the flow (never over an icon, so repeated clicks can't hit an action), the one at the
  edge disabled, not hidden. Home button on top, 48px like the icons; Data, theme toggle (auto → light → dark) and ✎ (actions editor) at the bottom.
- Tab right-click menu: "Download" and "Delete note"; delete removes note + tab immediately, no confirmation
  (choosing it is the confirmation). The × in the `[+]` note list keeps its `confirm()` (small target, easy to
  misclick). Deletion is permanent; a trash was offered and not requested.
- Note names: any string, the field is `name` (a "virtual file name"); duplicates are allowed.
- Closing a tab: untouched or empty → just closes; edited → close panel asks for a name; an empty note created
  here (`created` flag) is deleted. Notes opened from the list are never deleted by closing.

## Code notes

- Structure: `platform/` is the only place with `chrome.*`; `shared/` is used by everything; `shell/` is the frame
  (screens, sidebar, home, actions editor, data dialog); `apps/<id>/` holds an app with its own CSS. An app's screen is
  `#app-<id>` in `newtab.html`; ids of its elements share a prefix (`tr-`, `bd-`).
- MV3 CSP forbids inline scripts → `shell/theme.js` is a classic script in `<head>` that applies the saved theme
  from `localStorage` before first paint.
- `[hidden] { display: none !important; }` is global, and `border-radius: 0 !important` on everything.
- The data model is documented at the top of `shared/db.js`; users keep their data across updates, so a change
  of stores or records needs a database `VERSION` bump with conversion (see PUBLISHING.md). The server doesn't know
  the model (a record is `{store, id, rev, updatedAt, deleted, data}`), so new stores and fields need no server change.
- `db.js` is the only code that touches IndexedDB. Writes are transactions (no Web Locks needed); after a commit
  `onChange` listeners on this page (`local: true`) and on other pages (BroadcastChannel `ntab-db`) hear
  `{store, ids, remote}` (`remote`: written by the sync). Tracker and board simply reload their store on a change;
  notes update the open tabs only. While a sync server is set, writes of synced stores also go to `outbox` in the
  same transaction. A wipe posts `reset`: every page stops writing and reloads.
- `shared/sync.js`: one page per browser syncs (Web Lock `ntab-sync`), the others get its status over the
  BroadcastChannel `ntab-sync`; the `device` record "sync" is the configuration (Connect / Disconnect write it, the
  syncing page follows).
- Editor performance: the textarea value is cached in `editor.js`; in wrap mode line heights are measured on a
  hidden mirror, cached per line text, and only visible gutter numbers are drawn. Keep typing cost low on big
  files (about 16 ms per keystroke on a large file was the last measurement).
- The tab bar updates in place (rebuilds only when the order changes). Drag-reorder uses `sortable()` in `util.js`.
- `views` in notes.js = per-tab cursor/scroll; `onScroll` saves it. `shell/view.js` is the screen state (home / app id).

## Testing

No test framework. `test/` holds a headless-Chrome harness driven over the DevTools protocol (raw CDP; Playwright/Puppeteer/browser MCP
were considered and declined, keep it dependency-free):

- `test/stub.js` mocks `chrome.runtime` (the favicon URL); the data is the test page's own IndexedDB.
- `test/run.sh [dir]` copies the sources into `dir` (default `/tmp/newtab-test`), makes `test.html` (newtab.html
  with `stub.js` injected before `main.js`), serves it on `localhost:8765` and starts headless Chrome with CDP on
  port 9333. Re-run the copy after editing sources (or kill the server/Chrome and run it again).
- `test/cdp.mjs` has helpers (`newPage`, `closeTab`, `ev`, `type`, `click`, `shot`, `ok`, `inDb`, `dbAll`,
  `resetData`, `actionList`, `openApp`); `test/extension.mjs` runs the real unpacked extension (its own headless
  Chrome over a DevTools pipe) for what the localhost page can't show (CSP, the sandboxed render frame, the sync from the
  extension's origin); `test/sync.mjs` runs the real server and three origins of the test page as devices (its own
  headless Chrome trusting the test certificate); `test/web.mjs` serves the repo
  like Pages and checks the PWA (service worker, offline, update, the web platform); `test/example.mjs` is a smoke test, `notes`, `tracker`, `board` and `data`
  (backup, import, reminder, routes, actions editor) cover the rest (`node test/<name>.mjs`, `SHOTS=dir` for
  screenshots; Node 22+ for the global WebSocket). A page must load once before `inDb` (it creates the database);
  `resetData()` empties it and sets the actions, reload afterwards.
- Pages start at home; click `#links .<app id>` (or `openApp(P, id)`) to open an app. File pickers: catch the
  `<input type=file>` and feed it with `DOM.setFileInputFiles` (see `test/data.mjs`). Background pages run timers
  about once a second, so allow 1.5 s for their saves. Use two pages for cross-tab sync tests. The stub's favicon cache is `/fav/<host>.png` (run.sh puts one for `s1.test`); other sites fall back to
  letters in the harness.
- Scenarios covered earlier by throwaway scripts (before 2.2.0's storage, rewrite as needed): autosave max-wait,
  drag reorder (tabs and actions), wrap gutter alignment and typing speed, flyout, theme cycle and persistence,
  actions editor (add it back, save warning), sidebar wheel scroll under the flyout and edge arrows.
